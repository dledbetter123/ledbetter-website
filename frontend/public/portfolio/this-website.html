This Website

The site you're on, and the AI you're talking to. It runs on serverless AWS: React on S3 behind CloudFront, and one Go Lambda running LedbetterLM, David's AI librarian. A fast model chats, and code questions go to an agent that reads David's GitHub repos live.

Frontend

React (Create React App), built to static files in a private S3 bucket and served through CloudFront with Origin Access Control. A CloudFront Function rewrites extensionless paths to index.html for client-side routing, and a response-headers policy sets HSTS, a Content-Security-Policy and the usual hardening headers. Editable content (the intro paragraph, the knowledge base, the résumé) loads from S3 at page time, so copy changes need no rebuild.

Backend

One Go Lambda (arm64, provided.al2023) behind an API Gateway HTTP API at /api/*, same-origin with the site. API keys come from Secrets Manager at cold start. Before the June 2026 rebuild, the site ran as Go and React containers on ECS/Fargate behind Application Load Balancers.

Deploys

GitHub Actions runs on every push to main: it builds the React app, syncs it to S3, invalidates CloudFront, then builds the Go Lambda and updates the function. AWS access goes through GitHub OIDC, so no long-lived access keys are stored.

How a chat turn runs

StepWhat happens
1. CapsPer-day request counts (global and per IP) and spend caps (per browser session and per day) live in DynamoDB and are checked before any model call.
2. Probe guardA pattern check and a short classifier call screen each message. A flagged session moves to a guard model that has no repo tools.
3. CataloguerWhen the first message looks code-bound, the Lambda invokes itself asynchronously and runs a Gemini research agent over the repos: up to 8 tool rounds inside a 95 s budget, under the 120 s Lambda timeout. Its fact sheet is cached for the session for an hour and handed to the chat model.
4. Worker loopThe chat model answers, calling list_my_repos, list_repo_files and read_repo_file as needed: up to 5 tool rounds plus a forced text answer, with an 18 s soft budget that keeps the turn under API Gateway's 30 s limit.
5. Side effectsThe turn goes onto an SQS FIFO queue, one message group per session and deduplicated per turn, so the reply returns at once. A worker writes the turn to a private, encrypted S3 bucket under a content-hash key and sends the notification email, with a dead-letter queue behind it.
AI agentsA known AI crawler's first contact gets a static greeting: no model call and no spend.

Gemini as the session starter

Workers AI models go cold on a low-traffic site, and a cold load can outlast the request timeout. So each turn prefers Cloudflare and falls back to Gemini, and a DynamoDB marker tracks whether Cloudflare is warm.

Warm

Cloudflare served in the last 180 s

The turn waits up to 20 s for Workers AI.

Cold

A 6 s probe, then Gemini

The cold attempt itself starts Cloudflare's model load, so a later turn finds it warm and traffic rotates back to Cloudflare.

Accounting

Billed to whoever answered

Each turn's cost and logs go to the provider that actually served it, and conversation logs record the provider, model and token counts, so later comparisons are exact.

Pricing the switch

Before moving off Gemini, David priced the chat both ways. 26 logged Gemini turns cost $0.3375 in total, ~$0.013 a turn, dominated by a ~3,250-token system prefix re-sent on every model call plus billed thinking tokens. A token model calibrated on that traffic predicted $0.32, within 5% of the bill, and then priced the same 26 turns on Workers AI.

The bake-off

Each model ran with the real system prompt and repo tools on a simple question, a repo lookup that must emit a tool call, and a privacy rule it must not break.

Model history

  • LedbetterLM started on Google's Gemini.
  • Primary inference moved to Cloudflare Workers AI for cost, with Gemini kept as the warm-start fallback.
  • On Cloudflare it first ran Meta's Llama 4 Scout, then Mistral Small 3.1 (24B) while the priority was following a long set of behavior rules without drifting.
  • It went back to Llama 4 Scout once the agent leaned into exploring the repos. Under the multi-round tool loop the 24B model sometimes fabricated ungrounded specifics, such as claiming Terraform or Docker after reading files that mentioned neither, while Scout emitted cleaner structured tool calls and stayed grounded in what it found.
  • In September 2026 the Gemini Pro alias moved to a model with no free tier, every call returned 429, and the fallback and the cataloguer went down with it. The fallback and the cataloguer now run gemini-flash-lite-latest, set by an environment variable, so the next alias move is a config change.

Repo access and security

What the agent can read

  • Public repos are open to the three read-only tools.
  • Private repos are deny-by-default. One stays invisible unless it carries a disclosure-rules file at its root, and those rules are injected as binding with every read.
  • A hardcoded never-list blocks sensitive repos entirely.
  • David's geometric-transformer research repos are description-only: the tools return only their READMEs, and fenced code is stripped from any reply about them.

How the site is protected

  • Operator mode, David's private way to update the knowledge base, sits behind passkey/WebAuthn login over constant-time HMAC-SHA256 session tokens.
  • Deny-by-default authorization for private resources.
  • Origin verification: the API answers only through CloudFront, and the raw API Gateway URL returns 403.
  • Rate limits, per-session spend caps and API Gateway throttling.
  • A guard model for probing attempts. The first design had the chat model flag probes itself through a rule in its long system prompt, and it flagged 0 of 8 subtle probes. A short single-purpose classifier call on the same model caught 34 of 34 probes and passed 34 of 34 ordinary questions (two runs each over 17 + 17 cases, p50 0.7 s).
