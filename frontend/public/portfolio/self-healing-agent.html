The problem it solves

Several releases can come out in a day, and the cadence keeps increasing. On each build, UI issues and OS quirks break the automation engineering team’s test code.

  • Every break was an engineer’s ticket: grab it, triage the failure mode, then code and validate the change.
  • One test piece can fail in several ways, and a larger plan in about a dozen.
  • Hundreds of plans can run in a suite at a time, across several suites.

The agent takes on that repair work, so engineers are freed up for other problems.

What the agent does

Each piece serves that loop: telling which failures are real, and writing the code that heals them.

  • Explores a world model. David developed a world model that treats screens and the transitions between them as a sandbox to explore; the agent lives in a gym where writing code is its lever toward healing the automation engineering team’s test plans.
  • Repairs code through David's harness. He designed the in-house harness, modeled after LangGraph, that performs the repair, treating the model as a swappable reasoning engine with a local Gemma 4 as the tool caller. LangGraph itself could not be used: the way the test devices communicate with the agent kept it from working in quick succession, so David developed his own serial communication protocol for them.
  • Repairs its plan online. David's parser turns the Swift test code into its syntax tree (AST), a tight projection of how the code should behave that serves as a control-flow prior. The agent is taught to measure incoming automation for deviations from that prior, and heals them.
  • Explores code as a partially observable Markov decision process (POMDP), so the agent acts on true divergences and ignores false error reports.
  • Gets its measurements from an async Python probe manager that runs outside the agent and delivers consistent raw metrics into the agent flow without adding latency.
  • Learned from its own heals. David built a corpus by running the harness with Claude as the reasoning engine, which let him perform instruction fine-tuning (IFT) of Gemma 4 on online plan repair on a Mac Studio. The fine-tuned Gemma 4 now runs the agent on its own in place of Claude; it is deployed in the lab and is projected to save $15,000 a month in token spend.
  • Reports to a dashboard David built, which monitors the agent's runs across the device gym. Opened to the greater QA org, it lets teams schedule jobs and keep up with their automation, saving 3–6 hours per person, per day, across the organization.
  • Runs alongside a fleet. David owned the deployment of a fleet of autonomous AI agents on an internal server spread across 3 Macs: the 3 Mac Studios act as ML-capable operators over a virtual distributed computing environment where tests run on deployed VMs that act as test devices and can talk to each other. He also built a local load-balancing cluster of lightweight agents serving LLM capabilities across applications.
