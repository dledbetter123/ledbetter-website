Kernel Mailbox Simulation

An interprocess-communication mailbox written as Linux system calls in C. Mailboxes are nodes of a binary search tree, each node manages a FIFO queue of messages, and mutex locks protect the shared structures. David ran it in a Linux VM on IBM Cloud.

What David built

  • Mailbox operations as Linux system calls written in C, so processes exchange messages through the kernel.
  • Mailbox management in a binary search tree: every node of the tree is a mailbox.
  • A FIFO queue of messages in each node, so a mailbox hands messages out in the order they arrived.
  • Mutex locking around the shared tree and queues, so only one caller changes them at a time.
  • A Linux virtual machine on IBM Cloud to build and run it.

Why each part

System calls

The kernel holds the mailboxes

Separate processes have separate memory, so the mailboxes live in the kernel, and every send or receive crosses into it through a system call.

Binary search tree

Ordered mailboxes

A binary search tree keeps mailboxes in key order, so finding one walks a single path from the root instead of scanning every mailbox.

FIFO queue

Messages in arrival order

New messages join at the tail and receivers take from the head, so a mailbox delivers messages in the order they were sent.

Mutex

One change at a time

Two processes can call in at once. The lock lets one caller at a time change the tree or a queue.
